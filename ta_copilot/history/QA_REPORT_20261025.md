## Detailed Reproductions & Fixes

### R2-01 — Monitor omits WAN-excused failures in the current partial hour from `failures_during_wan_outage`
- **Reproduction**:
  - At `now = START + 5400` (1.5 hours into the run) with a corroborated WAN outage at `START + 3700..3760` (in the current partial hour `[START + 3600, START + 5400)`) and 2 `COLLECTION_FAILED` (`Network or TLS failure`) events at `START + 3710` and `START + 3720`, `shakedown_check.report(now)` returned `wan_outages=['home WAN outage 10-20 01:01:40 (modem)']` and `failures_during_wan_outage=0`.
- **Fix**:
  - Computed `wan_failures = sum(1 for e, k, _ in events if k == 'COLLECTION_FAILED' and in_window(e))` across all lookback `events` (matching `upstream_failures`), while keeping per-hour `wan` exclusion inside the completed-hours loop.
  - Added `AdversarialQA20261025Tests.test_r2_01_monitor_counts_wan_failures_in_current_partial_hour` in `btc-readiness/qa/study005r2_release/tests/test_shakedown_qa.py`.

### R2-02 — Monitor `WHERE epoch >= since` drops `COLLECTOR_STOP`, `REBOOT_RESUME`, and boundary events preceding the 12-hour lookback window
- **Reproduction**:
  - At `now = START + 24*3600 + 1800` (`since = START + 12*3600`), with `COLLECTOR_STOP` (`orderly stop`) at `since - 10` and `COLLECTOR_START` (`restart`) at `since + 320`, slot `since` missed its checkpoint band `[since + 300, since + 330]`. Because `COLLECTOR_STOP` was at `since - 10`, `events` (`WHERE epoch >= since`) omitted it and `shakedown_check.report(now)` returned `problems=['1 missed slot(s) with no reason (the seal gate needs one for every miss)']`.
- **Fix**:
  - Loaded `all_events = c.execute('SELECT epoch,kind,detail FROM runtime_events ORDER BY epoch').fetchall()` for `wan_windows`, `near` (filtering `and d`), `REBOOT_RESUME`, and `COLLECTOR_STOP`/`COLLECTOR_START` slot explanations, while slicing `events = [row for row in all_events if row[0] >= since]` for the 12-hour failure counts.
  - Added `AdversarialQA20261025Tests.test_r2_02_monitor_uses_stops_preceding_lookback_window` in `test_shakedown_qa.py`.

### R2-03 — Seal gate validation gaps in `check_wan_outages`, `check_shakedown`, and `shakedown_rate_ok`
- **Reproduction**:
  - Passing a summary without `upstream_5xx` and with an hourly row `{'failure_rate': 0.0, 'failed_during_wan_outage': 999}` (omitting `failed` and `successful`) bypassed the count check on line 239 (`if 'failed' in row or 'successful' in row or 'failed_upstream_5xx' in row or has_upstream:`) and passed `check_shakedown`.
  - Passing `slots: True, enrolled_checkpoints: True, missed_slots: []` or an hourly row with `failure_rate: None, partial_hour: False, inactivity_explained: True` when `missed_slots` was `[]` also passed `check_shakedown`.
- **Fix**:
  - Included `'failed_during_wan_outage' in row` in the hourly count-check condition in `check_wan_outages`.
  - Enforced `type(slots) is int`, `type(enrolled) is int`, and list-of-dict structure checks in `check_shakedown`.
  - Updated `shakedown_rate_ok(row, missed=None)` so an `inactivity_explained: True` hour with `failure_rate: None` and `partial_hour: False` verifies that all 4 slots in that hour are present in `missed_slots`.
  - Added `AdversarialQA20261025Tests.test_r2_03_seal_gate_rejects_unbacked_wan_counts_bool_slots_and_fake_inactivity_explained` in `test_shakedown_qa.py`.

### R2-04 — First-slot boundary alignment between `release_tool.shakedown_summary` and `shakedown_check.report`

### TA-01 — `tally_report.record_problem()` & `TallyLogger.settle_pending()` validation gaps
- **Reproduction**:
  - `record_problem({"type": "minute", "ticker": "W1", "minute": 1, "captured_at": "2026-10-07T00:01:00Z", "history_stale": 123})` returned `None`, crashing `tally_report.minute_section()` with `TypeError: argument of type 'int' is not a container or iterable`.
  - `record_problem` accepted `"rsi": float("nan")` inside `timeframes["1m"]`, crashing `log_tools.merge()` on `json.dumps(..., allow_nan=False)`.
  - An `open` row without `close_time` passed `record_problem()` and caused `TallyLogger.settle_pending()` to raise `KeyError: 'close_time'` and latch `feed.errors["tally_settle"]`.
- **Fix**:
  - Extended `tally_report.record_problem()` to validate `stale` and `kalshi_stale` (`bool` if not `None`), `history_stale` (`list` of `str` if not `None`), `samples` (nonnegative integer count if not `None`), and timeframe `rsi` / `macd_hist` (`finite_or_none`).
  - Guarded `if ticker in self.settled or not row.get("close_time"): continue` in `TallyLogger.settle_pending()`.
  - Added `test_ta01_record_problem_rejects_malformed_flags_samples_and_nan_indicators` and `test_ta01_settle_pending_skips_rows_missing_close_time` in `ta_copilot/test_qa_20261025.py`.

### TA-02 — Fractional-second ISO `close_time` ordering in `refresh_proxy`, `prune_memory`, and `proxy_section`, plus `prepare()` state reset
- **Reproduction**:
  - Because ASCII `.` (`0x2E`) sorts before `Z` (`0x5A`), raw string sorting on `close_time` ordered `"2026-10-07T00:15:00.500000Z"` before `"2026-10-07T00:15:00Z"`, causing `TallyLogger.refresh_proxy()`, `TallyLogger.prune_memory()`, and `tally_report.proxy_section()` to misorder closes and disagree with `all_tickers` (which sorted by `parse_ts`).
- **Fix**:
  - Updated `TallyLogger.prune_memory()`, `TallyLogger.refresh_proxy()`, and `tally_report.proxy_section()` to sort by parsed UTC timestamp (`parse_ts` / `parse_iso_ts`, with fallback to string `close_time` and ticker tie-breaker).
  - Cleared `opened`, `settled`, `results`, `closes`, `expirations`, and `value_pending` at the start of `TallyLogger.prepare()`, and bounded orphan tickers in `self.settled` during `prune_memory()`.
  - Added `test_ta02_closes_sorted_by_parsed_timestamp_and_prepare_resets_state` in `ta_copilot/test_qa_20261025.py`.

### TA-03 — `Feed.update_spot()` crashes when Coinbase ticker omits `best_bid` or `best_ask`
- **Reproduction**:
  - `parse_coinbase_spot()` parses `best_bid` and `best_ask` via `optional_float`, returning `None` when absent, but `Feed.update_spot()` called `finite_float(bid)` and `finite_float(ask)`, raising `TypeError: float() argument must be a string or a real number, not 'NoneType'`.
- **Fix**:
  - Updated `Feed.update_spot()` to parse `bid` and `ask` via `optional_float` and reject `<= 0` when present.
  - Added `test_ta03_update_spot_accepts_missing_bid_ask_and_rejects_nonpositive_bid_ask` in `ta_copilot/test_qa_20261025.py`.

### TA-04 — Transient `/markets` error during confirmed exchange closure resets `exchange_closed`
- **Reproduction**:
  - When `exchange_closed` and `exchange_closed_probe` were `True` within the 60 s `EXCHANGE_STATUS_REFRESH` window, a single `poll_market()` call where `/markets` raised an `OSError` skipped the cached closure check (`if not selected and not listing_error:`) and set `exchange_closed = False`.
- **Fix**:
  - Updated `Feed.poll_market()` so a fresh cached `exchange_closed_probe` within `EXCHANGE_STATUS_REFRESH` is honored when `not selected`, while only probing `/exchange/status` when `not listing_error`.
  - Added `test_ta04_poll_market_preserves_cached_exchange_closed_across_transient_listing_error` in `ta_copilot/test_qa_20261025.py`.

### TA-05 — Watcher state validators accept booleans and `NaN`/`inf` as numbers
- **Reproduction**:
  - Because `bool` is a subclass of `int` in Python and `float("nan")` is a `float`, `ta_watch.valid_state()` and `acer_watch.load_previous()` accepted `True`/`False` and `NaN`/`inf` for `last_sent_at`, `feed_since`, `kalshi_stale_since`, and `fails`.
- **Fix**:
  - Updated `ta_watch.valid_state()`, `acer_watch.load_previous()`, and `acer_watch.dashboard_problem()` to reject `bool` and non-finite floats.
  - Added `test_ta05_watchers_reject_boolean_and_nonfinite_state_values` in `ta_copilot/test_qa_20261025.py`.
