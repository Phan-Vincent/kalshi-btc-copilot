**1. Malformed ledger accepted across the Pacific-day boundary — daily accounting can be wrong**
Severity: **P2**

Exact reproduction:
```python
now = '2026-09-28T07:00:00Z'
limits = json.load(open('risk_limits.json'))
proposal = {
  'ticker':'KX','side':'YES','price':'.50','price_tick':'.01',
  'requested_quantity':'100','available_quantity':'100',
  'fee_bound_per_contract':'.02','stress_reserve_per_contract':'.01',
  'fee_bound_verified':True,'fee_bound_reference':'synthetic',
  'fee_bound_as_of':'2026-09-28T07:00:00Z',
  'fee_bound_scope':'all_supported_quantities_including_fragmentation_and_rounding',
  'fee_bound_valid_until':'2026-09-28T07:00:15Z',
  'market_verified':True,'market_as_of':'2026-09-28T07:00:00Z',
  'market_valid_until':'2026-09-28T07:00:15Z'}
ledger = {
  'verified':True,'verification_reference':'synthetic',
  'captured_at':'2026-09-28T06:59:59Z',  # 2026-09-27 23:59:59 PDT
  'day_pacific':'2026-09-28',
  'account_value':'500','realized_gross_loss':'0',
  'positions_and_pending':[]}
```

- Expected: `DATA_UNAVAILABLE`, `eligible_quantity == '0'` — the ledger snapshot timestamp is the **previous** Pacific day, contradicting `day_pacific='2026-09-28'`; the input is malformed and the daily-loss bucket is not trustworthy.
- Actual: `CONDITIONALLY_ELIGIBLE`, `eligible_quantity == '47.16'`, `max_loss == '24.9948'`. I ran this and confirmed it.
- Why: `_evaluate` compares `ledger['day_pacific']` only against the day derived from `now`, never against the day derived from `captured_at`. Freshness (`age = 1s ≤ 60`) passes, so a snapshot taken 1 second before midnight can be labeled as today's, understating today's realized gross losses/committed risk.
- Minimal fix: compute `utc(ledger['captured_at']).astimezone(ZoneInfo(DAY_ZONE)).date().isoformat()` and require it to equal both `ledger['day_pacific']` and `local_day`, otherwise raise `InvalidInput`.
