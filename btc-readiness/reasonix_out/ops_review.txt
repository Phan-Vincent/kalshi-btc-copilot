## CONFIRMED (executed)

**1. P1 — Sleep overlapping an in-flight request (≈15–20 s) still halts the store as `CLOCK_DISCONTINUITY`.**
`btc_copilot.measured()` now uses `continuity_clock()` for latency, so a sleep that spans a request inflates `latency_seconds`. `study_policy.check_clock` line 45 then raises `ValueError('Request clock discontinuity or staleness')`, and `publish()` line 243 string-matches `'clock'` and calls `_halt('CLOCK_DISCONTINUITY')`.
Repro (`scratch/probe1_sleep_during_request.py`): take `f.fixture()` snapshot, set one request to `started_at_epoch=epoch-16.2`, `finished_at_epoch=epoch-0.2`, `latency_seconds=16.0` (wall and sleep-inclusive mono both advanced 16 s — pure sleep, no step):
```
check_clock raised ValueError: Request clock discontinuity or staleness
publish raised: ValueError Request clock discontinuity or staleness
store.halted = True | HALTED file = True
```
Expected: sleep ≠ wall step, so this poll should degrade/be dropped, not halt. Actual: permanent halt. The `0<=elapsed<=15` / `now-start>20` bounds don't distinguish sleep from a step; only `abs(finish-start-elapsed)>1` does.
Fix: use the wall/mono mismatch check to halt on steps, but treat sleep-inflated (`elapsed>15`, `now-start>20`) as staleness → `ReadError`/degradation, or measure the 15 s request budget with a sleep-exclusive clock.

**2. P1 — `settle_one` still uses `time.monotonic()`, so sleep during a settlement GET halts.**
`coherent_runtime.py:262/266` (`started=time.monotonic()`, `elapsed=time.monotonic()-started`) was not migrated to `continuity_clock`. On macOS `time.monotonic()` excludes sleep, so any sleep during `client.market()` makes `abs(ended-now-elapsed)>1` and halts `SETTLEMENT_CLOCK_DISCONTINUITY`.
Repro (`scratch/probe2_settle_sleep.py`): patch `coherent_runtime.time.monotonic` to advance 0.1 s while `wall()` advances 16 s across the GET:
```
settle_one raised: RuntimeBlocked Settlement clock discontinuity
store.halted = True | HALTED file = True
```
A ~2 s sleep already trips it. This directly violates “system sleep must NOT halt collection.”
Fix: `started/elapsed` via `continuity_clock()` and, as above, halt only when wall and mono disagree (real step); treat a wall-consistent long GET as degradation.

**3. P2 — One non-`ReadError` settlement failure kills the whole run uncleanly, bypassing the new resilience policy.**
`settle_one` records `SETTLEMENT_FAILED` (degradation, non-halting) then re-raises, but `run_authorized` only catches `ReadError` around `reconcile_one`. A single malformed-but-transient upstream payload (`RuntimeBlocked('Settlement ticker mismatch')` or `TimeoutError`) escapes, and `finally: store.close(clean=False)` leaves `RUNNING` behind, blocking resume for operator review.
Repro (`scratch/probe3_settle_transient.py`): `store.settle_one.side_effect=[RuntimeBlocked('Settlement ticker mismatch'),False]` with the test lifecycle fixture:
```
run_authorized raised: RuntimeBlocked Settlement ticker mismatch
store.close calls: [call(clean=False)]
store.settle_one calls: 1
```
Expected: degradation + continue (like collection polls), stop after `MAX_CONSECUTIVE_FAILURES`. Actual: run dies on the first occurrence with no `HALTED` marker but a persistent `RUNNING` block.
Fix: in the loop, catch the same non-halting settlement exceptions (or have `settle_one` convert them to `ReadError` after recording), and only re-raise when `store.halted` or the gate is revoked.

**4. P3 — A wall step forward across `release_utc` stops cleanly instead of halting.**
The loop only compares `wall()` to `release_utc`; a large forward step there hits `break` → `clean=True` → `RUNNING` removed, no `HALTED`, so the skipped tail of the study leaves no review marker and a restart can resume with a silent gap.
Repro (factory fixture, `wall` = `iter([release-3600, release+3600])`): returned `{'status':'STOPPED','cycles':1,...}`, `store.close(clean=True)`.
Fix: track wall vs `continuity_clock()` across loop iterations (or a last-wall reference in the DB) and halt when the two diverge by >1 s even if that crosses `release_utc`.

**5. P3 — Mid-run publication integrity mismatch is treated as transient degradation for ~10 minutes.**
If `publication`/`generations` digests stop matching, `store.state()` (called outside `Collector.once`’s `try`) raises `RuntimeBlocked('Publication digest mismatch')` with `store.halted == False` (repro: corrupt `publication.state` → `state()` raises, `store.halted = False`).
